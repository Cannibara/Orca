# Pre-2013 13F history: design

Last verified: 2026-11-17
Status: owner asked for the work on 2026-11-17 ("fully utilise pre-2013 SEC 13F data ... display pre-2013 results"); built from this spec the same day, after a design review (its changes are folded in below and listed in section 13).

## 1. Goal and success criteria

Funds' holdings, returns and P&L go back to Q1 1999 instead of Q2 2013, and the site shows them (the 15y and Max tabs, the quarter tables, the charts).

Done when:
- Every 13F-HR and 13F-HR/A filed on EDGAR from 1999 to the XML switch in 2013 has been read, and each one is either stored or counted with the reason it was left out.
- A sample check shows the stored filings agree with the filers' own declared totals (section 5), and the share that agree is reported to the owner.
- Berkshire Hathaway's fund page shows quarters from 1999, and the 15y Famous funds list is no longer two funds long.
- Nothing published before 2013 is labelled wrong on the site (negative quarter indexes, section 9).
- Post-2013 figures do not change, except where pre-2013 history now joins a fund's tracking segment.

## 2. Facts (checked 2026-11-17)

| Fact | Evidence |
|---|---|
| Electronic 13F-HR filings start with filings made in Q2 1999 (period Q1 1999). Before that EDGAR has a few dozen "13F-E" filings per quarter. | EDGAR `full-index/{1997,1999}/QTR*/form.gz`: 1999 Q1 has 26 13F-HR, Q2 1,603 |
| ~2,000–3,500 13F-HR and ~250–450 13F-HR/A filings per quarter; ~160,000 in all to mid-2013 | same indexes, 1999–2013 |
| The SEC's XML bulk data sets start with filings made in 2013 Q2 (`2013q2_form13f.zip`), and only XML filings are in them | data-sets page |
| So Q1 2013 is also missing today: Berkshire's published history starts at q 1 (Q2 2013) | `data.orcaetf.com/fund/1067983/summary.json` |
| A sample of 607 filings averaged 71 KB and downloaded at ~5 per second one at a time | scratch test |
| Before the XML switch the holdings table is free text (fixed-width columns, sometimes tabs, quotes or one field per line), rarely HTML; the summary page usually declares the table's entry count and value total | the sample |
| OpenFIGI's mapping finds no listing for dead companies' CUSIPs (Enron, Lehman, Bear Stearns, WaMu, Gillette) unless asked with `includeUnlistedEquities`; then it returns their FIGIs (LEHMQ, WAMUQ, ...) | two calls 2026-11-17 |

## 3. Scope

In: 13F-HR and 13F-HR/A filings listed in the EDGAR full index for 1999 Q1 to 2013 Q3 (filing quarters) whose accession is not already stored from the bulk data sets or the live feed. Their holdings join the existing per-quarter lake tables with `source = "legacy"`. Prices, T-bill rates and the web app follow back to 1999.

Out: 13F-E and paper filings (no machine-readable table), confidential-treatment tables the filer left out, 13F-NT notices (as today). Rebuilding the engine. New site features: no 20y or 25y tab (Max shows the full history).

## 4. Ingest

New module `pipeline/orca/sec/legacy.py`; new stage `ingest_legacy` in `run/ingest.py`.

- Index: `https://www.sec.gov/Archives/edgar/full-index/{year}/QTR{n}/form.gz` (one request per quarter, ~2–5 MB). Its rows have the daily index's layout, so `live.parse_daily_index` reads them.
- Download: each filing's submission text file, as the live feed does (`live.ARCHIVES + path`), through the shared SEC client (rate limit 8 per second). Up to 4 downloads run at once, 64 at a time, so the limit, not latency, sets the pace; the client's token bucket got a lock.
- CIK: the SEC header's first filer (the bulk data sets' choice), not the index row (the index lists a joint filing once per filer, by name).
- A filing that has an XML information table (a few in 2013) is read by the live reader; every other one by the text reader below.
- Header facts come from the SEC header, not the free text: `CONFORMED PERIOD OF REPORT` (period), `FILED AS OF DATE`, the first filer's `COMPANY CONFORMED NAME` and CIK. A paper filing (`<PAPER>`) is skipped.
- Amendment type (13F-HR/A only): the cover page's checked box, "[X] is a restatement" → restatement, "[X] adds new holdings entries" → new holdings, otherwise unknown (ignored by `select_reports`, as today).
- Order and checkpoints: index quarters oldest first. A quarter's filings are parsed and then ingested together, and only then is the quarter recorded in `state.legacy_done` ("1999Q2", ...). The budget is checked before each quarter (~3,000 filings, ~8–10 minutes), so a cut loses at most one quarter's downloads.
- Precedence: bulk, then live, then legacy for the same accession (`holdings.select_reports` / `_bulk_first_unique` extended). Accessions already stored are not downloaded.
- Each filing's check (section 5) is written to a new lake table `legacy_checks` (accession, cik, period, filed, form, status, rows, invalid_rows, parsed_value, declared_value, declared_entries). It is private, like the rest of the lake, and is what the reliability report is computed from.
- Running it: a new command `python -m orca.run backfill` (`run.weekly.run_backfill`) reads filings until 40 minutes of the budget are left, then maps the new CUSIPs and vendor tickers and fetches older prices (section 7) with the rest; it computes and publishes nothing. The Pipeline workflow gets an input `backfill` (alone: with `full` or `home_only` the step fails), which skips the upload and the cache purge. The funds it touches wait in `state.pending_funds` for the next ordinary run. Its last line says what is left (`"left": {"quarters", "price_histories"}`). Two backfill runs are expected (~160,000 downloads at 8 per second ≈ 5.5 h).

## 5. Reading a text table, and checking it

A row of the information table is found by its CUSIP, the one field with a checksum:
1. Text of every document of the submission except binary ones (graphics, PDF, uuencoded). HTML tables become lines with tab-separated cells; SGML tags (`<TABLE>`, `<S>`, `<C>`, `<PAGE>`) are dropped; quotes are blanked; tabs expand to 8 columns.
2. CUSIP: 9 characters, alone or written 6-2-1 with spaces or hyphens (`025816 10 9`, `205363-10-4`), with at least one digit in the first six and a valid check digit. If a filing yields no valid rows this way, it is read again taking 8-character CUSIPs (`36960410`; three digits first) and computing the check digit.
3. Value and shares: the first two numbers after the CUSIP (`$`, thousands commas and a glued `SH`/`PRN` allowed). If the CUSIP's line has fewer than two, the next lines are read (up to 4, stopping at the next CUSIP): wrapped rows and one-field-per-line tables. `PRN` and `PUT`/`CALL` are taken from the words after the numbers.
4. Continuation rows (Berkshire lists one CUSIP per group of managers): a line with no CUSIP whose first two numbers end in the value and shares columns of the row above, with nothing but numbers before them, is another row of that CUSIP. A line that adds up the rows above (a total or page subtotal) is not.
5. Invalid rows: a line whose first two numbers line up with the table's but whose CUSIP is missing or fails its check digit (typos, 7-digit SEDOLs) is not stored (it could not be mapped), but is counted for the check.
6. Issuer: the text before the CUSIP on its line (title of class not separated). It only feeds the name fallback of CUSIP mapping.

The check compares the rows with the summary page's "Information Table Entry Total" and "Value Total" (a unit note such as "(x$1000)" skipped; a "$" amount under an "Entry Total" label read as the value total, a common slip):

| Status | Rule | Stored |
|---|---|---|
| `ok` | stored rows (+ invalid rows) = declared entries, or their value is within 0.5% of the declared total (× 1, × 1000 or ÷ 1000: filers mix units) | yes |
| `close` | value within 2% | yes |
| `unverified` | no declared totals at all, and every CUSIP found had its numbers | yes |
| `mismatch` | anything else with rows | no |
| `no_rows` | no rows: table omitted (confidential), notice filed as 13F-HR, table split across pages by column, unreadable | no |
| `empty` | declared zero entries | no (a fund's holdings are never wiped on a text reading) |
| `paper` | paper filing | no |

A filing not stored is a missed quarter for its fund: one is carried (`holdings.fill_gaps`), two or more start a new tracking segment, as today.

Result on the 607-filing sample (568 text filings, 1999–2013), as first built: 74.3% `ok`, 3.0% `close`, 12.5% `unverified`, 6.3% `mismatch`, 3.0% `no_rows`, 0.9% `empty`; after the famous-funds fixes below: 76.9% `ok`, 2.3% `close`, 10.2% `unverified`, 6.5% `mismatch`, 3.2% `no_rows` (89.4% stored; a few doubtful filings the first rules let through are now refused) (the first prototype had 66.5% `ok` and 12.3% `mismatch`). So 89.8% are stored: 77.3% agree with the filer's totals and 12.5% declare none to check. Berkshire's Q4 2004 filing reads exactly (66 rows, $35.76bn, both as declared). The rest of the mismatches are one-field-per-line tables with uncoded foreign rows, three-number value columns and filers' own wrong totals. `tests/test_legacy.py` keeps a synthetic case of each layout.

Famous-funds test (owner's request, 2026-11-17): every pre-XML 13F-HR and 13F-HR/A of 40 famous funds filing since 2005 or earlier (Berkshire, Baupost, Greenlight, Soros, Renaissance, Tiger Global, Pershing Square, Bridgewater …), 2,494 filings. Three rounds of fixes came out of it (glued `SH` columns, a 9-digit voting count passing the check digit, glued CUSIPs and decimals, totals in "1 335 366 000" or "$43.7 Billion", dropped leading zeros, foreign rows' repeats, "Values Total", lone unmarked amendments as the quarter's report, and stricter fallback readings after one stored "132200 SH" as a code). Final: 91.2% stored (86.7% checked), 6.2% mismatch, 1.6% no rows, 1.0% empty. History reaching back before 2013 in one unbroken tracking segment: median 11.5 years; 28 of 40 funds 10 years or more, 36 five or more (Berkshire 14.5, Dodge & Cox, Ruane, Southeastern, Baillie Gifford, Soros, Greenlight, CalPERS 14.2). Short ones and why: Maverick, Baupost, Viking, Icahn, Coatue filed no 13F-HR for some quarters (a real gap of 2+ starts a new segment); D. E. Shaw and Two Sigma declared empty early tables; Harris, Renaissance, Kahn Brothers, Markel still have layouts the reader rejects. OpenFIGI on a sample of their pre-2013 CUSIPs: 99.4% of the dollars held are identified (64.0% as listed today, 35.4% only with delisted securities included), so the delisted pass (section 6) is essential; by count, 43% of the long tail of small holdings is not found.

Why filings have no totals although every filer manages over $100M: the totals are typed by the filer on the summary page, and many left it blank ("______"), left it out (17–20% of filings in 1999–2001, under 3% by 2011–13), wrote the label without "Total", or put the number below blank lines. The reader now reads the last two, and checks a table's own TOTAL line when the summary is blank.

Two more rules came out of the sample: the "Entry Total" count matches only on coded rows (with uncoded rows added it let half-read tables through), and a heading line that puts `SHARES` before `VALUE` swaps the two numbers (0.7% of the sample).

Units: VALUE is in thousands before 2023 (`config.VALUE_DOLLARS_FROM`). A legacy filing whose median value per share is above 1 (over $1,000 a share in thousands) reported dollars, and is stored as dollars. A stock with market prices is valued at our price anyway; this matters for stocks valued at the reported value.

## 6. Securities

New CUSIPs are mapped by the existing stage, with these rules for a CUSIP first held before 2013 (CUSIPs first held from 2013 on are mapped exactly as before):
- Not found by OpenFIGI's ordinary mapping: asked again with `includeUnlistedEquities` (`securities.map_unlisted`, method `unlisted` in `cusip_map`; never remapped). Without it every company that died before today drops out of the pre-2013 books, which biases old returns upwards (the losers vanish).
- Never matched by name (the SEC-name fallback), and never given a by-name alternate ticker: old General Motors' name is new GM's, and a name match would merge the two (one stock id; GM's held span from 1999 would then trip the reuse rule and cost today's GM its prices).
- An unlisted listing's ticker is kept only if it looks like one (`8181760Q` is a vendor code), and such a security gets no SEC CIK, SIC or shares outstanding (today's holder of its old ticker is someone else).
- Such stocks usually have no vendor prices and are valued at the reported value per share, as unpriced stocks are today.

## 7. Prices and T-bills

- `prices.HISTORY_START` becomes 1999-01-01: a stock fetched for the first time gets its history from then.
- A stock held before 2013 whose stored bars begin more than a week after its first held quarter (and after 1999-01-01) gets only the missing range fetched, 1999-01-01 to the day before its first stored bar (`prices.fetch_heads`, `run.market.backfill_price_heads`), once (`state.price_backfilled`). A full refetch was the first plan; it would have downloaded and stored every 2013+ bar again and asked the SEC for ~10,000 share counts. This gives pre-2013 closes, VWAPs, dividends and, most important, splits (without split factors a split looks like a purchase). It runs in the backfill, and in ordinary runs after the regular price refresh (stage "price history"), so today's prices come first.
- The vendor-ticker rules are unchanged, but a stock also held from 2013 on is checked over its 2013+ span only (`run.market.held_spans`): its pre-2013 quarters must not cost it today's ticker (a ticker's current line often begins after a company's first 13F quarters, and before that it has no vendor prices anyway). A stock held only before 2013 is checked over all of it.
- `rf.START` becomes 1999-01-01, and a stored T-bill table that starts after 1999 is fetched again (`update_rf`), so pre-2013 quarters have a risk-free rate (Sharpe, Sortino) instead of 0.

## 8. Engine, compute and the workbook

- The engine already works on any integer quarter (Python floor division). Tests add negative quarters.
- Fund compute grows with the history (~48 min today); the time budget already stops it between batches and leaves the rest pending, so a first full compute can take two or three runs.
- `verify` (the monthly check) leaves out funds owed a recompute: after a backfill they differ from what is published until a run publishes them.
- The coverage health gate (`coverage_median`) is the median over active funds: funds that stopped filing before 2013 hold mostly companies gone since (unpriced) and would sink it.
- Workbook formulas that use `MAX(... × (q + 1)) − 1` as "none" and `">=0"` tests assume q ≥ 0; they move to an offset of 100 (q ≥ −56 always).

## 9. Web

Quarter math breaks for negative q in six places that use `q % 4` (`lib/format.ts` `qLabel`, `fund/fmt.ts` `qShort`, `lib/live.ts`, `charts/PriceChart.tsx`, `fund/positions.ts`, `fund/StockPanel.tsx`): `-1 % 4` is −1 in JavaScript. They use one helper `quarterOfYear(q) = ((q % 4) + 4) % 4`. Clamps at quarter 0 (`StepChart`, `PriceChart`, `StockPanel`, `whatif.ts` `buildRows(..., 0, ...)`) take the data's first quarter instead. The 15y empty-list note on Home loses "the SEC's data starts in 2013".

## 12. Risks and limits

- Unverified filings (no declared totals, ~12%) are stored on the strength of the row rules alone.
- Stocks with no vendor prices have no split factors; a split then reads as a trade. `split_suspect` flags these.
- Pre-2013 holdings in dead companies are valued at the filer's reported value; dividends of unpriced stocks are missing (as today).
- Run time and lake size grow (raw holdings roughly double); the first full compute may need two runs.
- Rows without a valid CUSIP are left out, as in the XML era.
- A fund with two rejected filings in a row starts a new tracking segment there, and only the latest segment is computed, so its history before the gap is not shown. Failures cluster by filer (a layout the reader cannot read fails every quarter). To be measured after the backfill: the share of funds whose segment reaches back to their first legacy quarter.
- `empty` filings (declared zero entries) are not stored, so the previous quarter is carried; the XML era stores an empty table as an empty book.
- Text 13F filings made after 2013 Q3 for older periods are not read (the XML rule makes them rare).
- `q-56` part names sort as text (q-01 < q-56 < q000); nothing reads quarter parts in time order.

## 14. Measured before merge (2026-11-18), and the second review

Every pre-2013 filing of 40 famous funds (2,494) and of 100 random 13F filers (2,381), read with the final reader:

| Measure | Famous 40 | Random 100 |
|---|---|---|
| Filings stored | 91.8% | 92.6% |
| Pre-2013 fund-quarters shown (first to last filing, one unbroken history) | 85.6% | 88.2% |
| Lost: fund did not file (real gaps) | 5.3% | 6.2% |
| Lost: unreadable filings (3+ in a row, or at the end) | 9.1% | 5.6% |
| Median absolute quarterly return (engine, reported prices only) | 5.9% | 5.4% |
| Fund-quarters beyond ±25% (mostly 2008–09 and share-count typos) | 3.1% | 2.5% |

- Unreadable filings: a quarter the fund filed but whose table could not be read is now carried from the last readable quarter, at most two in a row (`holdings.fill_gaps(unreadable=...)`, from `legacy_checks`), which took the random funds from 84% to 88% shown. The rest is mostly four famous filers (Harris to 2011, Renaissance, Kahn Brothers, Markel).
- Splits: genuine splits (2, 3, 3/2, 4, 5, 10) touch ~0.4% of a fund's book a quarter. With no split data at all that would understate old returns by ~0.7 points a year; about half of that value is on stocks with vendor split data, and `splits.infer_splits` reads the rest from the filings when two or more holders agree (q ≤ 0 only). Expected remainder: ~0.1–0.3 points a year, visible mostly on single positions in companies gone since. An earlier estimate of 3–4 points a year counted 25% and 33% adds as splits and was wrong.
- Share-count typos (one quarter 4×+ off, value normal): 28 in the random funds' data, none moving a book by over 5% at market prices; 2 fund-quarters of one famous fund (Tweedy Browne, 2009). Not repaired (they exist in the XML era too).
- OpenFIGI on the famous funds' pre-2013 CUSIPs: 99.4% of the dollars identified, 35.4% only among delisted securities.

Second (pre-merge) review, changes made: split inference needs two agreeing holders, no 5-for-4 / 4-for-3, q ≤ 0 only; a delisted company takes only a vendor line that has ended (Tiingo's "T" is today's AT&T back to 1984); no by-name ticker for stocks held only before 2013; lone unmarked amendments only for text filings and only with no original that quarter; the price-history stage recovers a dead run's prices first; header periods after the filing date or before 1998 rejected; an exception in one filing records `read_failed` instead of stopping the backfill; rows kept as frames. Noted, not changed: a backfill run may need three runs, not two; non-prerendered fund pages (beyond the 15,000 largest books) still load as the app.

## 13. Changes from the design review (2026-11-17)

1. No name fallback or by-name alternates for CUSIPs first held before 2013; unlisted pass first (section 6).
2. Vendor-ticker span from 2013 for stocks also held since (section 7).
3. T-bills refetched when the stored table starts after 1999.
4. Older prices: only the missing range, after the regular refresh, no share-count lookups.
5. `verify` skips owed funds; the coverage gate counts active funds.
6. `backfill` also maps CUSIPs and vendor tickers and fetches older prices; `US_TICKERS_PER_RUN` 1,000 → 10,000 (100 OpenFIGI requests).
7. Source rank bulk > live > legacy made explicit; `build_holdings`' guard checks any non-bulk source; legacy CIK from the header.
8. Workflow: `backfill` alone, no upload or purge.
Not taken: storing near-miss tables (wrong numbers are worse than less history) and carrying rejected quarters as filed (stale books); both wait for the measurement in section 12.
